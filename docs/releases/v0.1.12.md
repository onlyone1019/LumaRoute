# LumaRoute 0.1.12 · Build 42

新增链式代理、订阅下载方式选择和局域网共享，并修复后台服务注册冲突与更新后的自动重连。

## 本次更新

- **链式代理**：在“代理 → 链式代理”选择前置节点或策略组和落地节点，生成可用于分流的独立链路。支持编辑、停用、删除及完整链路测速，保留原节点；正在被规则引用的链路不能直接移除。
- **订阅下载方式**：添加或编辑远程订阅时可选择直连、系统代理或 LumaRoute 代理。每个订阅独立保存选择，手动和自动更新沿用；旧订阅仍默认直连。LumaRoute 代理需先有可用配置，下载方式不会自动改变业务流量出口。
- **局域网共享**：可将混合代理端口共享给私网设备，必须设置用户名与密码；默认关闭，控制接口仍仅监听本机。监听或认证变化会重启内核，使旧监听和旧密码失效；普通备份不携带共享密码，恢复后共享保持关闭。
- **后台服务修复**：本机服务使用独立的服务名称和 XPC 端点，避免与系统缓存的另一种注册冲突。旧安装通过“完成更新”迁移；安装后确认进程真正启动，失败时回退。修复本地签名构建迁移时的权限错误，以及重试断开 XPC 导致内核无法自动重连的问题。

保留现有原生扁平 UI、规则缓存复用及此前的日志页、规则页和连接页性能修复。

## 验证与边界

本版完整 Swift 测试 104 项、脚本测试 42 项通过，Apple Silicon 和 Intel CLI 各通过 218 项回归断言。真实 Mihomo 测试确认双跳链路、规则引用保护、保存失败回退与节点消失时拒绝直连；局域网测试确认认证、回环例外、控制接口隔离、密码替换及关闭共享生效。

后台服务修复已在 Apple Silicon 上完成真实安装、管理员授权迁移、自动启动和应用重开验收；通过 19790 端口的 HTTPS 请求返回 HTTP 204。Clash Verge 可继续运行，系统代理保持使用其 7890 端口。未进行整机重启验收。

链式代理已通过真实 Mihomo 与本地双跳 CONNECT 代理验证；订阅下载覆盖代理下载、直连失败、持久化及旧配置兼容；共享配置覆盖认证、私网限制和备份处理。相关验收记录见仓库 docs。Intel 提供交叉构建与 Rosetta 验证，未在 Intel 真机上完成系统代理、TUN 或服务迁移验收。

## 安装与更新

需要 macOS 14 或更新版本。M 系列 Mac 选择 `arm64`，Intel Mac 选择 `x86_64`。

0.1.8 及以后版本可在应用内点击“检查更新”，下载完成后选择“安装并重新启动”。更新保留订阅、规则、节点选择和设置；需要同步后台服务时，在 macOS 管理员授权窗口确认。手动替换时，先关闭 LumaRoute 的系统代理和 TUN、退出应用，再替换原安装位置的应用。

与其他代理工具共存时使用不同端口；默认混合端口为 19790、控制端口为 19791。下载使用系统代理时，需先在现有代理客户端开启系统代理。

安装包使用本地 ad-hoc 签名，未经过 Apple 公证。浏览器下载后如被系统阻止，请按“系统设置 → 隐私与安全性”的提示允许打开，或按 README 从源码构建。
