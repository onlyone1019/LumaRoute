# Build 26：统一组合分流编辑器

组合订阅的“分流规则”同时支持完整域名、域名后缀、域名关键词、IPv4 / IPv6 网段、进程名称和可执行文件路径。可从应用选择器填入主程序路径。规则可停用、排序或删除。

出口可选择组合成员订阅、组合及源订阅的策略组、直连或拒绝连接。策略组从当前草稿成员的缓存生成，不读取另一个正在运行的配置的策略组。保存与成员更新时检查有效出口；失效出口须重选或停用。

批量添加支持空行、每行一个匹配内容或 `TYPE,匹配内容`，使用统一出口。批量输入先整体校验再加入草稿，错误包含行号；拒绝重复条件、非法网段、规则注入和超过 256 条的输入。网段按网络地址规范化；应用匹配和重复检查遵循内核的大小写不敏感行为。

## 规则与验证范围

实际优先级保持为：自定义规则 → 组合分流规则 → 优先规则订阅 → 基础规则 → 补充规则订阅 → 兜底出口。修改应用于新连接。

“分流验证 · 当前草稿”本地预览自定义规则及编辑中的组合规则，显示命中条目、匹配方式、内容和目标出口。可输入域名、目标 IP、已有解析 IP、进程名称或路径。遇到前序规则缺少 IP / 进程信息时停止判断并提示补充，避免误报后续命中。预览不解析 DNS，不发起网络请求，不模拟远程规则集或最终自动选择的节点；未命中明确说明继续交给后续规则，真实出口可在连接页检查。

IP 规则使用 `no-resolve`，不会仅因检查网段而额外触发解析。进程匹配要求流量进入本应用，实际进程识别依赖已授权后台服务；主程序之外的辅助联网进程应根据连接页显示的信息设置。

## 兼容与持久化

保留既有 `domainRoutes`、`domain`、`profileID` JSON 字段；新增可选 `target` 作为策略组 / 内置出口。旧数据没有该字段时继续绑定原订阅 UUID。SQLite 无需迁移；组合仍作为独立本地配置保存，单订阅模式及其自定义规则不变。应用分流页提示组合中另有的应用规则并提供管理入口。

## 验证

- Release 构建及代码签名校验。
- CLI `verify`：203 项断言，包含兼容读取、规范化、网段边界、批量失败原子性、重复检查、匹配顺序、信息不足、持久化和无效出口。
- `composition-routing-check`：12 项真实内核断言，以两个本地 HTTP 代理区分订阅 A/B，验证七种匹配、大小写一致性、策略组、直连、拒绝和停用。应用匹配在管理员进程中测试，与正式后台服务权限一致。IPv6 测试请求由内核匹配后经订阅 B 到本地模拟代理，不依赖公网 IPv6。
- `composition-check`：15 项组合、provider/URI 混合及切回单订阅的真实请求回归。
- `composition-dns-check`：3 项成员节点 DNS 真实测速回归。
- 实际 AppStore + 私有 SQLite：9 项保存、候选来源、重开、失效出口拒绝与失败保留验证。
- 设置保存与按需刷新、运行时容错回归。
- 原生 UI：批量行号纠错、七种匹配菜单、订阅 / 策略组出口、完整域名 / IP / 应用预览、信息不足提示、应用选择器及取消草稿；测试草稿不写入用户组合。
