# 多订阅组合与域名分流验收（Build 23）

日期：2026-10-15。Apple Silicon macOS，本机构建安装，Mihomo v1.19.32。

## 使用方式

1. 在“订阅”添加至少两份普通订阅或本地配置。
2. 点击“组合订阅”，填写名称，勾选 2 至 16 个来源。
3. 选择“基础配置”：沿用这一份订阅的 DNS、原有规则及规则提供者。
4. 选择“兜底出口”：聚合所有成员节点，或固定使用某份订阅的节点组。
5. 添加域名分流，选择“完整域名”或“域名后缀”，再选择目标订阅。域名后缀包括该域名及子域名，可启停、排序、删除；最多 256 条。
6. 保存并启用。之后也可在“规则 → 域名分流”修改绑定，在“代理”选择“聚合节点”或各订阅节点组的出口。“聚合自动”提供延迟选优。
7. 点击任一普通订阅的“启用”，即恢复原有单订阅模式。已保存的组合仍可再次启用。

域名分流在规则模式下生效。输入域名本身，例如 `example.com`，不包含协议、路径或通配符；国际化域名使用 ASCII/Punycode 表示。

## 组合行为

- 组合保存为独立本地配置，引用普通订阅；不能嵌套组合。组合定义保存在现有 SQLite 业务库中，旧数据无需迁移。
- 节点、策略组及代理提供者按来源命名，避免机场之间的同名冲突。原策略组的 `include-all` 等设置只包含本订阅的来源。
- Build 25 修复成员节点服务器 DNS 丢失：基础订阅继续控制网站 DNS，为成员中直接声明的域名节点保留本订阅显式指定的节点服务器解析策略。详见 [聚合节点 DNS 修复记录](composition-node-dns-2026-10-15.md)。
- DNS 中指定的策略组出口随来源重命名，节点密码等普通文本保留原值，包括其中的 `#` 字符。
- 执行优先级：自定义规则 → 域名分流 → 优先规则订阅 → 基础订阅规则 → 补充规则订阅 → 兜底出口。
- 组合的自定义规则与单订阅的自定义规则分别保存；策略和规则订阅沿用按配置绑定的机制。
- 成员订阅更新时，正在使用的组合会重新生成并应用。下载、校验或保存失败时保留上次可用配置；内容相同时仍只更新元数据。
- 备份包含组合定义及成员缓存，恢复时重新生成组合。被组合引用的普通订阅不能直接删除，需先从组合移除。
- HTTP provider 未指定下载出口时使用 DIRECT 引导，避免首次加载时通过空节点组下载自身；明确指定的出口保留并按来源映射。
- 每个组合最多 16 份订阅，生成的配置最大 8 MB。只合并所选基础配置的全局设置，其他订阅贡献节点、策略组及代理提供者。
