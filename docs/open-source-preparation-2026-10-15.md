## 审计范围和方法

1. 使用有权限的 GitHub 账号读取远端分支、标签、仓库私有状态和四个 Release 的完整附件元数据。逐一核对所有远端 heads / tags 在本地存在且对象 SHA 相同。
2. 覆盖 12 个可达提交、257 个唯一历史 blob、17 张历史图片。Git 历史 diff 与全部可达 blob 分别使用官方 Gitleaks v8.30.1 默认规则扫描，启用二层解码和完整脱敏，不设宽泛排除或忽略名单。Gitleaks 工具下载后核对官方发布校验值。
3. 历史图片使用中英文 OCR，并人工检查两张总览图。当前截图显示合成演示订阅和示例域名；未发现可读的真实订阅链接或凭据。
4. 四个 Release（Build 17、19、21、28）共 14 个附件，全部与 GitHub 附件 SHA-256 核对。覆盖五套应用：四个 ARM 版本和 Build 28 Intel 版本。分别验证 DMG 镜像、ZIP / DMG 内应用逐文件一致性、嵌套签名、文件清单；提取文本、发布说明及可执行文件可读字符串后扫描。
5. 补查私钥标记、带凭据 URL、本机路径、私有 IP 示例及提交作者元数据。没有向真实订阅商或其他服务发送凭据有效性验证请求。
