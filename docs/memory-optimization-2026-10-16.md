# 日志导出与页面缓存内存优化

2026-10-16，基线为 `6f58000`，Apple Silicon / Release。本轮只修改日志导出和页面缓存，不修改页面布局、主题、网络配置、内核或后台服务。

日志导出文本从 `LogsPage.body` 移至实际点击“导出诊断”时生成。保存期间使用固定快照，成功、失败和取消均释放导出文本；恢复实时日志时释放暂停快照。

页面切换仍复用原宿主。最后一次切页 60 秒后，仅回收非当前的日志、连接页面渲染树；日志搜索、筛选、暂停快照、选中项和连接搜索、筛选、排序、选中项由窗口内的小型状态对象保留。重建时恢复滚动位置及连接表格列宽。当前页、正在导出或编辑连接规则的页面不回收。设置、规则、订阅、代理等页面继续保留，避免丢失草稿和展开状态。

## 串行复测结果

相同的 2000 条合成日志、300 个连接、160 个节点及 8 个策略组；真实 RootView、页面和 AppStore，不调用 bootstrap，不连接真实内核。前后使用相同 Release 核心库。先完成基线，再编译并运行优化版，避免编译和两个宿主并行影响切页计时。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 所有页面访问后物理内存 | 134.8 MiB | 117.6 MiB |
| 40 次日志更新后物理内存 | 158.7 MiB | 140.9 MiB |
| 设置页空闲 61 秒后物理内存 | 174.5 MiB | 93.0 MiB |
| 再次访问日志、连接、设置后物理内存 | 178.6 MiB | 106.3 MiB |
| 普通切页布局耗时中位数，28 次 | 316.0 ms | 125.3 ms |
| 普通切页布局耗时 P95，28 次 | 351.4 ms | 162.2 ms |
| 空闲后首次返回日志页，单次 | 342.4 ms | 266.1 ms |
| 空闲后首次返回连接页，单次 | 354.4 ms | 248.8 ms |
| 40 次日志更新测试总耗时 | 11.08 s | 3.55 s |

内存为 `task_info(TASK_VM_INFO).phys_footprint / 1024²`。切页从导航赋值开始，包含随后一个主队列回合及同步布局、display；普通切页统计排除首次访问。它不是输入到屏幕最终呈现的端到端延迟，也不是所有硬件、订阅规模或当前已安装进程的内存承诺。日志更新测试包含每轮 10 ms 的等待与布局，并非纯业务执行时间。截图捕获也会产生分配，两版采用相同流程。

首轮隔离测量的空闲内存为 173.9 → 93.3 MiB，与串行复测方向一致。

## 复现

先构建当前 Release 核心依赖，然后在修改前保存基线并测量，再修改源码并测优化版：

```sh
./script/build_and_run.sh --build-only
python3 script/check_memory_usage.py --baseline
python3 script/check_memory_usage.py
```

脚本在首次基线运行时冻结 UI 源码，并固定首次捕获的 Release 模块和链接对象；后续重跑使用同一套依赖。`--label` 指定输出名称，`--run-only` 复用同名已编译宿主，`--interactive` 打开隔离人工验收窗口。运行锁确保这些测量串行执行。需要测试新的源码基线或核心依赖时，使用新的工作目录保留原始证据。

本次原始 JSON、PNG、导出文件和冻结源代码在 Git 忽略的 `work/memory-optimization-2026-10-16/`，最终报告为 `comparison.json`，串行原始报告为 `before-clean.json` 和 `after-clean.json`。
