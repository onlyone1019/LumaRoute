# Build 28：界面响应优化与验收

## 改动

- 后台服务心跳只在状态变化时写入 `serviceRunning` / `canRollbackGeo`，避免同值 `@Published` 赋值触发无关界面更新。保留真实状态变化的通知。
- 状态菜单按策略组、成员类型与顺序、配置列表、版本和端口判断结构变化。结构未变时复用菜单对象，更新勾选、启用状态、当前节点和测速信息；正在展开时推迟结构重建。缓存截断文字和列样式，高亮只更新前后两项；菜单关闭后停止其刷新定时器。缓存的配置操作按 UUID 重新取得最新配置，避免闭包使用旧内容。
- 页面切换与强制刷新分开：切页按缓存时效刷新，明确刷新命令仍可强制拉取；连接页去掉与导航刷新重复的首次请求。内核健康检查、后台恢复和配置变更后的失效处理保留。
- 增加小型 AppKit 页面宿主，首次访问才创建对应 SwiftUI 页，返回时复用；仅当前页接入窗口。保留搜索、展开、设置 / 规则草稿，已保存的组合分流随外部修改更新；未保存的组合草稿不会被同页重新出现无条件清除。宿主跟随窗口尺寸和外观，切页清理离开页面的第一响应者。
- `CompositionPolicyCache` 在独立 actor 上读取成员缓存、组合和解析策略组。每次先读取当前 SQLite 内容，再比较输入，命中时复用结果；成员内容变化即使元数据相同也会失效。仅保留一份候选缓存，不持久化，不改变数据库结构。错误和取消不返回旧结果，编辑器继续按当前任务 / 组合标识丢弃过期结果，保留 Build 27 的加载中误报修复。

## 测量方法

基线为 `f582cee` / Build 27；修改前源码保存在私有工作目录。前后编译为 Release 原生宿主，读取同一份用户 SQLite 私有副本和 `/proxies` 只读快照（14 个可见策略组）。宿主不 bootstrap、不启用代理、不连接用户在线控制器；刷新测试使用独立回环 HTTP fixture。

`script/check_ui_responsiveness.py --baseline` 编译基线，默认编译当前源码；`--run-only` 复用二进制，`--interactive` 用于 CUA 验收。脚本所需的 `before.sqlite`、`proxies.json` 与基线源码在 Git 忽略的 `work/ui-optimization-2026-10-15/`，不得提交用户数据。

先后顺序运行原生宿主，避免前后测量同时竞争 CPU。自动布局为每页 8 轮，去掉首次；菜单 15 次，去掉首次；候选查询 8 次，去掉首次。

### 限制

上述窗口测量不包含工具传递点击的时间，也不等同于物理输入到显示器出帧；未将自动布局、菜单和候选用时相加。可见窗口样本用于本机对照，数量不足以声称所有硬件上的 P95 保证。原生窗口仍有布局、框架和冷启动开销，不能据此宣称所有操作都已低于 50 ms。

首次候选读取仍需生成；本轮方法调用用时约 31 ms → 82 ms，后者还包含执行器调度及等待期间其他 UI 更新。没有将首次调用宣称为加速。新路径首次加载时 UI 执行器仍有任务执行，旧同步路径在同一测量段中为 0 次；优化收益是移走 UI 同步计算与后续查询命中缓存。
