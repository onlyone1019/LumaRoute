# VPS 订阅下载超时修复（2026-10-27）

## 原因与复现

添加 VPS 订阅时，下载在 TCP 连接阶段超时，尚未进入配置校验。原实现默认使用强制直连的 curl 传输，界面无法选择代理；即使 macOS 已有可用的系统代理，订阅下载也不会使用。

对同一 VPS 端口验证：直连在 6 秒连接期限内超时，未完成 TCP/TLS；经过现有本机代理则约 0.22 秒完成 TLS 握手。使用界面中的完整订阅地址，代理请求约 0.38 秒获得 HTTP 200、3308 字节的 YAML。

订阅完整地址、访问令牌、响应内容及节点凭据不写入本报告、命令参数或普通日志。真实地址与响应仅在本次权限受限的临时目录中验证，结束后清理。

## 改动

- “添加订阅”和“订阅设置”新增下载方式：直连、系统代理、LumaRoute 代理。
- `Profile.downloadRoute` 按订阅持久化；手动、批量及自动更新使用保存的方式；旧配置缺少此字段时仍为直连。
- 系统代理读取 macOS 对目标协议配置的 HTTP/HTTPS 代理，或 SOCKS 代理。没有可用地址时明确报错，不静默直连。
- LumaRoute 下载使用当前就绪内核的混合端口；未就绪时提示先启用可用配置，避免用尚未下载的 VPS 作下载前置。
- 将原直接传输封装更名为 `SubscriptionTransport`，支持显式代理。地址和代理配置通过 stdin 交给 curl；显式覆盖环境代理及绕过列表。
- 保留 HTTPS 证书校验、重定向限制、大小限制、超时与取消逻辑。规则订阅原有的直连重试仍使用相同行为。

## 验证

1. 先建立回归：本地 HTTP 代理能返回订阅，目标直连端口不可达；修复前选择代理仍失败，测试确认为红。
2. 修复后完整 SwiftPM 测试集 101 项通过。
3. 覆盖 HTTP/HTTPS 系统代理选择、SOCKS 回退、未配置代理、LumaRoute 未就绪、SQLite 重开与备份、旧配置默认值。
4. 保留原有 User-Agent、并发请求、订阅错误分类、链式代理和局域网共享测试。
5. 通过实际 `SubscriptionFetcher` 使用系统代理下载真实 VPS 订阅，取得 2 个节点，真实 Mihomo 配置校验通过，未忽略证书错误。

```sh
source script/build_environment.sh
swift test --build-system native --sdk "$SDK_PATH"
```

这解决订阅下载路径问题。导入后，VPS 的实际代理流量仍需在“链式代理”中选择机场前置；下载方式不会自动改变业务流量的分流。
